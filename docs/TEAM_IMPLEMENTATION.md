# 더뉴빌리지로 오세요 — 구현·협업 계획

> [스토리](STORY.md)의 확정 사항을 구현하기 위한 작업 계획이다. 개발자 간 화면·서버 계약은 [API 계약서](API_CONTRACT.md)를 기준으로 한다. 미정인 이야기 분기는 임의로 완성하지 않는다.

## 제품 범위

- 첫 공개 시연에서 **세 엔딩까지** 도달하는 것을 목표로 한다.
- 인물과의 **자유 대화**에 장소 이동·조사·핵심 선택용 버튼을 결합한다.
- 하나의 LLM을 사용하되, 선택된 인물의 페르소나·알고 있는 사실·현재 장면을 넣어 답변한다. 인물별 대화 내용과 플레이어가 발견한 공통 단서를 구분한다.
- AI는 인물의 대사를 생성한다. 지미의 실종, 지하실·사진·머리카락 발견, 호감도 검사, 차 키와 엔딩은 결정적인 진행 규칙이 처리한다. AI가 임의로 사건을 앞당기거나 비밀을 누설하지 않도록 한다.
- 호감도가 낮아도 즉시 사망하지 않는다. 축제에 가까워진 특정 시점에 검사하여 사건을 분기한다. 검사 시점·수치·결과는 [스토리 문서](STORY.md)의 협의 항목이다.

## 화면과 진행 상태

화면은 현재 장소의 배경, 대화 상대와 표정, 채팅, 주인공의 생각·발견 기록, 이동할 수 있는 장소를 보여준다. 장소와 인물은 현재 장면에서 허용된 것만 선택할 수 있게 한다. 답변에 맞는 이미지를 선택하며 고정 프로필 이미지만으로 끝내지 않는다. 베이스 코드의 [프로젝트 가이드](PROJECT_GUIDE.md)는 답변별 이미지를 결과 기준으로 둔다.

진행 규칙은 적어도 현재 장면·장소, 이용 가능한 인물·행동, 발견한 단서, 호감도, 차 키, 엔딩 여부를 다룬다. 화면은 서버가 제공한 **공개 가능한 진행 상태**만 표시한다. 숨겨진 단서나 판정 규칙은 화면으로 보내지 않는다. 새로고침 후 이어하기 여부와 실제 상태 저장소는 아직 결정하지 않았다. 이 선택은 API 계약을 바꾸지 않는 서버 내부 구현으로 다룬다.

세계관 자료는 인물별 지식과 장면별 공개 조건을 구분해 작성한다. 검색이 필요하다면 관련 사실이 실제 답변에 반영되는지 검증한다. 검색을 쓰지 않는다면 그 이유와 대신 검증할 기술 요소를 README에 설명한다.

## 단계별 구현·검증

1. **계약 확정:** [API 계약서](API_CONTRACT.md)와 스토리의 인물·장면·행동 ID를 두 개발자가 확인한다. 미정 분기는 명시적인 임시 상태로 남긴다.
2. **첫 구간 연결:** 이름 입력 → 지미 대화 → 이웃 한 명과 대화 → 장소 이동 → 집 복귀. 캐릭터 전환, 대화 문맥, 화면 갱신, 답변별 이미지를 확인한다.
3. **중간 사건:** 캐시의 부탁, 정육점과 지하실, 지미의 실종, 캐런의 집 사진 발견을 연결한다. 인물의 정보 누설과 장면 순서를 확인한다.
4. **축제·세 엔딩:** 확정된 호감도 검사와 차 키 규칙을 적용한다. 탈출·사망·동화까지 각각 도달하는 경로를 확인한다.
5. **공개 시연:** 공개 URL에서 처음부터 각 엔딩까지 테스트하고 모바일 화면, 이미지 로딩, 빈 입력, 모델 API 실패를 확인한다. 팀 README를 실제 동작에 맞게 고친다.

기존 `tests/`는 데모 앱의 동작을 검사한다. 구조를 바꾸면서 실제 계약에 맞게 갱신한다. 특히 호감도만 낮다고 즉시 죽지 않는 규칙, 차 키에 따른 결말, 장면 밖 비밀 누설 방지, 중요한 행동의 중복 실행을 확인한다.

## 두 엔지니어의 책임과 파일 경계

| 담당 | 책임 | 소유 영역 |
| --- | --- | --- |
| 팀장 엔지니어 | 장면·호감도·단서·엔딩 규칙, 인물별 LLM 대화, 요청 검증, 서버 상태와 통합 | `app.py`, `services/chatbot_service.py`, `services/generator.py`, `services/retriever.py`, 진행 상태용 새 모듈, `config/`, `data/knowledge/`, 서버 테스트 |
| 다른 엔지니어 | 장소·인물 선택, 채팅·생각 기록 화면, 배경·표정 이미지 전환, 답변별 이미지 선택 | `templates/`, `public/assets/`, `services/image_selector.py`, `data/images/`, 화면 테스트 |

양쪽 모두 [API 계약서](API_CONTRACT.md)를 읽고 구현한다. `image_selector.py`와 서버 사이의 호출 규격도 그 문서에 고정한다. 공유 파일인 `requirements.txt`, `README.md`, 이 문서들, `AGENTS.md`의 변경은 먼저 담당자를 정한다. 담당 영역 밖 수정이 필요한 경우 PR 전에 상대에게 변경 이유와 정확한 파일을 알린다.

## 저장소와 AI 에이전트 운영

- 원본 저장소에서 fork한 **팀장 소유 저장소**를 팀의 기준 저장소로 사용한다. 두 개발자는 각자의 브랜치에서 작업하고 팀장은 PR을 검토한 뒤 `main`에 병합한다. 로컬 `origin`이 실제 팀 fork를 가리키는지 `git remote -v`로 확인한다.
- `main`은 시연 가능한 상태를 유지한다. 작은 기능 단위로 PR을 만들고, 각 PR에 변경 내용·확인 방법·남은 문제를 적는다.
- AI 에이전트에는 담당 파일 범위, [스토리](STORY.md), [API 계약](API_CONTRACT.md), 이 계획을 함께 전달한다. 에이전트가 범위를 넘어선 수정이나 계약 변경을 제안하면 코드를 합치기 전에 두 개발자가 검토한다.
- 프로듀서는 캐릭터·장소 이미지, 영상, 인물별 공개 가능 정보와 금지된 스포일러를 정리해 공유한다. 엔지니어가 형식과 경로를 확인한 뒤 저장소에 반영한다.
- 비밀 키는 로컬 `.env`나 배포 환경 변수에만 둔다. 코드·문서·PR·스크린샷에 기록하지 않는다.

## 실행 환경

이 팀의 로컬 가상환경 활성화 명령은 다음과 같다.

```powershell
conda activate chatbot-base
```

패키지 설치와 테스트는 이 환경에서 프로젝트 루트의 `requirements.txt`를 기준으로 실행한다. `conda activate`는 기존 환경을 **활성화**하는 명령이며 환경 생성이나 의존성 설치를 뜻하지 않는다.

## 외부 에이전트 도구

Ponytail은 선택적으로 사용할 수 있다. 각 개발자의 로컬 에이전트에 설치하는 도구이며 저장소에 복사하거나 팀의 공통 필수 의존성으로 취급하지 않는다. 도구의 일반적인 간결화 지침보다 이 프로젝트의 스토리·API 계약·파일 소유권과 필요한 검증을 우선한다. 설치 상태와 훅 신뢰 여부는 각자 확인한다.
